## L22401 大數據與機器學習

### 第 1 題［中偏難｜有效批次與更新次數］

某資料集恰有 1,048,576 筆樣本。團隊使用 8 張 GPU 做同步資料平行訓練，每張 GPU 的 micro-batch 為 32，累積 4 個 micro-batch 後才執行一次 optimizer update。假設各 rank 的資料不重複、沒有丟棄尾批次，則每次更新的 effective global batch size 與每個 epoch 的 optimizer update 次數分別為何？

A. `128；8,192`  
B. `1,024；1,024`  
C. `256；4,096`  
D. `4,096；256`

### 第 2 題［難｜模型記憶體與平行策略］

一個 300 億參數模型即使 batch size 為 1，連同 Adam optimizer state 仍無法放入單張 GPU。團隊有 16 張 GPU，目前只使用傳統 DistributedDataParallel（每張卡各保留完整模型與 optimizer state）。哪項調整最直接處理根因？

A. 保持完整複本，只把 DataLoader worker 從 8 增加到 64  
B. 將 batch size 從 1 再除以 16  
C. 增加至 32 張 GPU，但仍讓每張 GPU 保存完整模型與 optimizer state  
D. 使用 FSDP／ZeRO 等參數、梯度與 optimizer state 分片，必要時再結合 tensor／pipeline parallelism、混合精度或 activation checkpointing

### 第 3 題［難｜同步訓練與 Straggler］

16 個 worker 做同步訓練，各 worker 的平均樣本數相近，但其中一個 shard 含大量超長序列，使該 worker 每 step 約需其他 worker 的 5 倍時間。監控顯示其餘 GPU 經常停在同步 barrier。下列處置何者最合理？

A. 依估計處理成本重新平衡 shards，並以長度 bucketing／動態批次控制每批 token 數；同時監控每個 rank 的 step time  
B. 把慢 worker 的 batch 增加 5 倍，使它一次處理更多資料  
C. 只提高其餘 15 個 worker 的時脈，因為同步訓練吞吐量由最快 worker 決定  
D. 永久刪除所有長序列，不檢查它們是否代表重要少數案例

### 第 4 題［難｜中斷續訓與可重現性］

使用可串流讀取的大型資料集訓練 20 天，工作會被搶占。團隊要求從 checkpoint 恢復後，盡可能接續相同的資料位置與最佳化軌跡，而不是重讀資料或跳過大量樣本。哪個 checkpoint 設計最完整？

A. 只保存模型權重；optimizer 與資料迭代器可任意重建  
B. 只記錄牆上時鐘時間，恢復時取「目前最新」資料版本  
C. 固定資料快照與 shard manifest，並保存模型、optimizer、scheduler、mixed-precision scaler、各 RNG state，以及 sampler／stream 的 epoch、shard 與 offset 狀態  
D. 每次恢復都改用新的隨機 seed，即可保證軌跡相同

## L22402 大數據在鑑別式 AI 中的應用

### 第 5 題［難｜極度不平衡與操作點］

疾病盛行率約 0.2%，篩檢流程要求 recall 至少 90%，並希望降低人工複核量。外部驗證結果如下：

| 模型 | ROC-AUC | 在 recall=90% 時的 precision |
|---|---:|---:|
| A | 0.96 | 4% |
| B | 0.92 | 12% |

哪個結論最適當？

A. A 必定較適合部署，因為 ROC-AUC 較高，操作門檻不再重要  
B. 兩模型都不需檢查盛行率差異，因為 AUC 與資料分佈完全無關  
C. 在既定 recall 限制下，B 的 precision 較高、預期複核量較低；應以 PR 曲線與目標操作點進一步確認，不能只看 ROC-AUC  
D. precision 只與模型參數量有關，不能由驗證資料估計

### 第 6 題［難｜延遲標籤與漂移監控］

信用風險模型上線後，真實違約標籤要 90 天才成熟。某次授信政策改版後，輸入特徵與分數分佈立刻顯著漂移，但目前尚無成熟標籤。哪個處理方式最合理？

A. 先檢查 schema、缺值與前處理是否異常，依客群分析 feature／score drift 並啟動警戒；保留改版前後資料，待標籤成熟後評估 discrimination、calibration 與決策成本，再據以決定是否重訓或回滾  
B. 只要任一 drift 指標超過門檻，就可斷定 accuracy 已下降相同比例並立即用未標記資料重訓  
C. 把模型自己的預測當成真實標籤，證明模型在改版後仍然正確  
D. 因為沒有即時標籤，所以連資料管線錯誤與輸入分佈都不需監控

### 第 7 題［難｜機率校準流程］

梯度提升模型的排序能力良好，但可靠度圖顯示：預測機率約 0.8 的樣本，實際正例率只有約 0.6。團隊需要把機率交給下游成本模型。下列流程何者最恰當？

A. 直接在最終測試集上調整門檻與校準函數，再用同一測試集報告成效  
B. 將所有預測機率乘以 `0.6/0.8`，且不再檢查其他區間  
C. 只比較 ROC-AUC；排序不變就代表機率已校準  
D. 以未參與基礎模型擬合的校準資料做 Platt scaling 或 isotonic regression，再用完全未碰過的測試集評估校準與決策效益

### 第 8 題［中偏難｜多類別平均方式］

四類故障的 class-wise F1 分別為 `0.98、0.75、0.40、0.05`，其樣本數依序為 `9,500、400、80、20`。業務明確要求四種故障同等重要。下列敘述何者正確？

A. 應只看 accuracy，因為它必定等於四個 F1 的平均  
B. macro-F1 為 `(0.98+0.75+0.40+0.05)/4=0.545`，能揭露稀有類別的低表現；仍應同時報告各類別指標  
C. weighted-F1 會給每個類別相同權重，因此最符合需求  
D. micro-F1 會自動對最少見的類別給最高權重

## L22403 大數據在生成式 AI 中的應用

### 第 9 題［難｜Sequence Packing 邊界］

訓練 causal language model 時，為提高 GPU 利用率，系統把多份互不相關的短文件塞入同一固定長度序列。若設計要求不同文件之間不能互相取得上下文，下列做法何者最正確？

A. 保留文件邊界 token，建立分段／block-diagonal causal attention mask，並適當遮罩跨文件邊界的 loss；位置編碼策略也要與分段設計一致  
B. 移除所有 EOS／邊界 token，讓模型自行猜測文件切點  
C. 只要最後 padding 到相同長度，標準 causal mask 就必然阻止前一文件影響後一文件  
D. 把文件順序隨機化一次，之後不需任何 attention 或 label mask

### 第 10 題［中偏難｜Instruction Tuning Loss Mask］

instruction-tuning 樣本包含 system、user 與 assistant tokens。訓練目標只希望對 assistant 回答位置計算 cross-entropy，但模型仍可把 system/user prompt 當作條件。以下哪個標籤處理最合適？

A. 將 assistant tokens 的 labels 全設成 `-100`，只學 prompt  
B. 將 system/user tokens 從 input 完全刪除，再要求模型生成回答  
C. `labels` 初始複製 `input_ids`，再把非 assistant 位置設為 loss function 的 `ignore_index`（常見為 `-100`）  
D. 所有 labels 都設成 padding token ID，避免 loss 過大

### 第 11 題［高難｜跨 Tokenizer 的語言模型評估］

兩個 causal language model 在完全相同、共 3,000 bytes 的評測文字上計分；特殊 token 與正規化規則已對齊，NLL 均以自然對數計。模型 A 的 tokenizer 產生 1,000 tokens，平均 NLL 為 1.8 nats／token；模型 B 產生 600 tokens，平均 NLL 為 2.0 nats／token。哪個判斷最恰當？

A. A 的 per-token perplexity 較低，所以不論 tokenizer 如何都已證明 A 較好  
B. 不應直接跨 tokenizer 比 per-token perplexity；可比較相同文字的總 NLL 再除以共同 byte 數，例如 A、B 的 bits-per-byte 約為 `0.866、0.577`  
C. token 數較少必定代表模型品質較高，因此不需使用任何 likelihood  
D. 先把兩邊的 token 數補成相同，就能直接比較原 per-token perplexity

### 第 12 題［難｜語料治理與可追溯性］

企業用數百個來源訓練生成式模型，部分來源日後可能撤回授權。哪個資料治理設計最能支援稽核與後續刪除／重訓判斷？

A. 只保留清洗後文字，來源 metadata 全部刪除以節省空間  
B. 訓練完成後才補一份籠統的「資料來自網路」聲明  
C. 只存文件雜湊，因為雜湊可自動證明取得與利用皆合法  
D. 為每份資料保留來源、取得時間、授權／同意狀態、內容雜湊、轉換 lineage 與資料集版本，並記錄各訓練 run 使用的 manifest

## L22404 大數據隱私保護、安全與合規

### 第 13 題［中偏難｜k-anonymity 的限制］

某資料發布表已將準識別欄位泛化，使每個 equivalence class 至少有 10 人，達到 10-anonymity。但其中一組 10 人的敏感欄位全都是同一種罕見疾病。最精確的判斷是？

A. 10-anonymity 已保證任何敏感屬性都無法推知  
B. 只要把 10 改成 11，就必然解決所有屬性揭露問題  
C. 仍有 homogeneity attack／屬性揭露風險；應評估 l-diversity、t-closeness 或更合適的隱私方法與威脅模型  
D. 將檔案由 CSV 改成加密 ZIP，即可在公開解密密碼後解決該問題

### 第 14 題［難｜Membership Inference］

外部 API 回傳完整類別機率。資安測試發現攻擊者可利用模型對訓練樣本異常高的信心，推測某人的紀錄是否曾出現在訓練集。哪項組合最針對此風險？

A. 只對資料庫磁碟加密；模型輸出與訓練方式完全不變  
B. 檢查 train/validation generalization gap，降低過擬合；視風險採 DP-SGD 等具明確隱私界線的方法，並限制輸出精度、查詢速率與可觀察資訊  
C. 將姓名改為固定無鹽雜湊，模型即可公開全部信心分數  
D. 擴大模型參數量並延長訓練，讓它更完整記住每筆資料

### 第 15 題［難｜聯邦學習與 Secure Aggregation］

醫院採 federated learning，不把原始病歷上傳，但中央伺服器會接收各醫院的模型更新。下列說法何者最適當？

A. 原始資料未上傳，所以模型更新不可能洩漏任何資訊  
B. secure aggregation 等同防止惡意 client 資料投毒，不需其他措施  
C. 只要每家醫院使用不同 optimizer，就自然形成差分隱私  
D. 模型更新仍可能洩漏資訊；secure aggregation 可讓伺服器只看到聚合結果，若需個體層隱私還應評估 clipping 與差分隱私，並另做 client 驗證及投毒防禦

### 第 16 題［難｜刪除請求與資料 Lineage］

使用者依法提出刪除請求；其資料已存在原始湖、特徵表、向量索引、訓練資料快照與備份，並可能影響既有模型。哪個處理流程最完整？

A. 以資料盤點與 lineage 找出衍生副本，對線上及可變更儲存傳播刪除／tombstone，讓備份依保留期隔離到期且復原時重套刪除紀錄，並依風險與法規評估重訓或可驗證移除及留存稽核證據  
B. 只刪除 CRM 畫面上的那一列，因為衍生資料不算資料  
C. 刪除原始姓名即可；向量、特徵與模型一律不需評估  
D. 立即覆寫所有歷史備份，即使會破壞法定保存、災難復原與其他使用者資料，也不需記錄過程
