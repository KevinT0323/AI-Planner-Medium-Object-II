## L22401 大數據與機器學習

### 第 1 題：B

每次 optimizer update 包含 `8 GPUs × 32 samples × 4 accumulation steps = 1,024` 筆樣本。每個 epoch 的更新次數為 `1,048,576 / 1,024 = 1,024`。

梯度累積增加的是一次參數更新前所涵蓋的樣本量；資料平行 world size 也要乘入 global batch。不能只用單卡 micro-batch 或只乘其中一項。

### 第 2 題：D

傳統 DDP 在每張 GPU 都複製完整參數、梯度與 optimizer state；增加同型 GPU 只提高資料平行度，不會降低單卡保存這些狀態的需求。FSDP／ZeRO 把狀態分散到不同裝置，tensor／pipeline parallelism 則可進一步切分模型計算。

DataLoader worker 只影響輸入吞吐；batch 已是 1，繼續縮小無法解決；仍保存完整複本的更多 GPU 也不處理根因。

### 第 3 題：A

同步訓練每一步都要等最慢的 rank，因此整體吞吐量由 straggler 限制。按 token 數或估計計算成本平衡 shard，再以長度 bucketing 或動態批次讓各批工作量接近，能直接降低等待時間；逐 rank 的 step-time 指標可驗證效果。

增大慢 worker 的 batch 會更慢；加速其他 rank 可能增加等待；直接刪長序列可能造成系統性資料偏誤。

### 第 4 題：C

完整續訓不只需要權重，還要 optimizer 動量、學習率排程、loss-scaling、亂數狀態，以及資料迭代位置。固定資料快照與 manifest 才能避免恢復時資料內容或 shard 邊界改變。

只存模型會改變最佳化軌跡；牆上時間不足以定位資料；改 seed 恰好會破壞可重現性。

## L22402 大數據在鑑別式 AI 中的應用

### 第 5 題：C

需求已固定 recall 至少 90%，此時 precision 直接影響每找出一個正例需要複核多少候選。B 在相同 recall 下 precision 為 12%，明顯高於 A 的 4%，因此更符合降低複核量的目標，儘管 ROC-AUC 較低。

ROC-AUC 彙整所有門檻，且在極低盛行率下可能看起來很高；部署仍須確認 PR 曲線、操作點、外部母體盛行率與機率校準。

### 第 6 題：A

feature／score drift 是沒有標籤時的重要領先訊號，也可提早發現 schema、缺值或前處理故障；但它本身不能證明真實 accuracy 已下降。先保留版本與分群監控證據，等 90 天標籤成熟後再評估 discrimination、calibration 和決策成本，才能判斷漂移是否傷害任務表現。

用模型預測充當真值只會循環驗證模型自己；未標記資料也不能在沒有目標與驗證設計下直接完成監督式重訓。完全等待標籤才看資料，又會錯失即時發現管線事故的機會。

### 第 7 題：D

Platt scaling 與 isotonic regression 都應在未參與基礎模型擬合的資料上學習，再以完全未接觸的測試集估計泛化後的 calibration error、Brier score 或實際決策效益。

只用單一區間乘常數通常無法修正整條可靠度曲線；ROC-AUC 衡量排序，不保證機率可信；用測試集調校再報告會產生樂觀偏誤。

### 第 8 題：B

macro-F1 對四個類別等權，計算為 `2.18/4=0.545`，因此不會讓 9,500 筆的多數類別掩蓋只有 20 筆且 F1 僅 0.05 的類別。樣本極少時指標不確定性也較大，所以仍應同報 class-wise 指標與支持度。

weighted 與 micro 類型的彙整會受多數類別主導；accuracy 並不等於 class-wise F1 的算術平均。

## L22403 大數據在生成式 AI 中的應用

### 第 9 題：A

一般 causal mask 只禁止看「未來」token，並不禁止後一文件看見同一 packed sequence 中較早的前一文件。若需求明定文件互相隔離，就要額外建立分段的 block-diagonal causal mask，並妥善處理邊界 label、EOS 與位置資訊。

padding 長度不提供文件隔離；刪除邊界讓問題更嚴重；隨機順序也不會改變 attention 的可見範圍。

### 第 10 題：C

assistant tokens 仍需要完整 prompt 作為條件，因此 prompt 應保留在 `input_ids`；但把非 assistant 位置的 label 設為 `ignore_index`，可使 loss 只累積在回答位置。

A 反向遮掉真正要學的回答；B 讓模型失去指令條件；全部設 padding 則沒有正確的回答訓練目標。

### 第 11 題：B

per-token perplexity 為平均 token NLL 的指數；tokenizer 切得較細或較粗會改變分母，因此不同 tokenizer 的數值不能直接排序。先加總同一文字的 NLL，再用共同的 byte 數正規化較合理：

- A：`1.8×1,000/(3,000×ln 2)≈0.866 bits/byte`
- B：`2.0×600/(3,000×ln 2)≈0.577 bits/byte`

因此在題目已對齊文字表示與特殊 token 的條件下，B 的 byte-normalized loss 較低。少量 tokens 只反映切詞方式之一，不能單獨代表模型品質；補 padding 也不會改變原始指標的分母定義。

### 第 12 題：D

來源、授權狀態、內容雜湊和轉換 lineage 能回答「這筆資料從哪裡來、如何被處理、進入哪些資料集與訓練 run」。版本化 manifest 又能界定受影響的模型與是否需要重建。

刪 metadata 會失去可追溯性；籠統聲明不能證明特定來源權利；雜湊只能協助識別內容，不會自行建立合法依據。

## L22404 大數據隱私保護、安全與合規

### 第 13 題：C

k-anonymity 只要求準識別欄位相同的群組至少有 k 人；若群組內敏感值完全一致，攻擊者即使不知道確切身分，仍能推知其敏感屬性。這是典型 homogeneity attack。

提高 k 一點不一定增加敏感值多樣性；l-diversity、t-closeness 等方法處理的是不同限制，但仍須配合資料用途與實際攻擊者背景知識評估。

### 第 14 題：B

membership inference 常利用模型對訓練資料與未見資料的信心或損失差異。降低過擬合、限制可觀察輸出，以及採用經正確設定與會計的 DP-SGD，可從模型與介面兩層降低風險；查詢稽核和速率限制也能提高大規模探測成本。

靜態加密不保護合法呼叫 API 後的輸出；替換姓名不會消除模型記憶；加大模型和過度訓練反而可能增加風險。

### 第 15 題：D

梯度或模型差分可能洩漏訓練訊息。secure aggregation 的主要作用是讓伺服器取得多個 client 的聚合更新，而非每個個別更新；若需要更明確的個體隱私界線，仍須考慮 clipping、noise 與隱私預算會計。

它也不等於資料投毒防禦；client 身分驗證、更新驗證、robust aggregation 等完整性措施是另一條風險線。

### 第 16 題：A

刪除請求必須沿 lineage 傳播到可識別的衍生資料，而不只是前台主表。不可任意改寫的備份通常需隔離、依保留期到期，並確保復原時重新套用 deletion ledger；模型是否需重訓或採可驗證移除，應依資料影響、可行性與適用法規評估。

B、C 忽略衍生副本；D 可能破壞其他法律義務與災難復原，而且沒有留下可證明已處理的稽核軌跡。
