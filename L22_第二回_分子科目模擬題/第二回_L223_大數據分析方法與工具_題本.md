## L22301 統計學在大數據中的應用

### 第 1 題［難｜未知長度串流抽樣］

系統只能依序讀取一次長度事前未知的事件流，希望在串流結束後保留「恰好 1,000 筆、不放回且對所有事件等機率」的樣本，記憶體只能存約 1,000 筆。最後實際共讀到 10,000,000 筆。哪個方法與包含機率的敘述正確？

A. 永遠保留最先出現的 1,000 筆；每筆事件的包含機率都是 0.01%  
B. 使用 reservoir sampling：先放入前 1,000 筆，第 `i>1,000` 筆以 `1,000/i` 機率進入並隨機替換一個既有樣本；結束時每筆的包含機率皆為 `1,000/10,000,000=0.01%`  
C. 每筆獨立以 0.01% 機率保留，即可保證最後恰好得到 1,000 筆  
D. 每讀滿一百萬筆只保留其中最後 100 筆；因每區塊保留數相同，所以事件順序不會造成偏差

### 第 2 題［高難｜穩健縮放與離群截尾］

訓練資料某連續特徵的近似分位數為 `Q1=8`、`median=20`、`Q3=44`。團隊規定先以訓練資料的 Tukey fences：

`[Q1 − 1.5×IQR, Q3 + 1.5×IQR]`

做 winsorization，再以 `(x − median) / IQR` 做 robust scaling。驗證資料有一筆 `x=140`。下列何者同時符合避免資料洩漏與上述定義？

A. 先把訓練與驗證資料合併重算分位數，再轉換 `x=140`  
B. 不截尾，直接得到 `(140−20)/44 ≈ 2.73`  
C. 先做 robust scaling，再把縮放後的值截在原始單位的 Tukey fences 內  
D. 沿用訓練資料參數，先將 140 截為 98，再縮放為 `(98−20)/36 ≈ 2.17`

### 第 3 題［高難｜時間點特徵與程式判讀］

交易表 `df` 含 `customer_id`、`event_time`、`amount`。在每一筆交易發生當下，模型需要「同一客戶先前最多 3 筆交易的平均金額」，不得使用目前交易或未來資料。假設同一客戶的 `event_time` 不重複，下列 Pandas 程式何者正確？

A.

```python
df = df.sort_values(["customer_id", "event_time"])
df["avg_prev3"] = (
    df.groupby("customer_id")["amount"]
      .transform(lambda s: s.shift(1).rolling(3, min_periods=1).mean())
)
```

B.

```python
df = df.sort_values(["customer_id", "event_time"])
df["avg_prev3"] = (
    df.groupby("customer_id")["amount"]
      .transform(lambda s: s.rolling(3, min_periods=1).mean())
)
```

C.

```python
df = df.sort_values(["customer_id", "event_time"])
df["avg_prev3"] = (
    df.groupby("customer_id")["amount"]
      .transform(lambda s: s.shift(-1).rolling(3, min_periods=1).mean())
)
```

D.

```python
df["avg_prev3"] = df.groupby("customer_id")["amount"].transform("mean")
```

### 第 4 題［中偏難｜稀疏特徵降維］

一個文件分析任務有 1 億份文件、200 萬個詞彙特徵，TF–IDF 矩陣極度稀疏。團隊希望在不建立稠密中心化矩陣的前提下，產生 256 維連續特徵供下游模型使用。哪個流程最合理？

A. 將全矩陣轉成 dense，減去每欄平均後執行完整共變異矩陣的 eigen-decomposition  
B. 先用全資料標籤挑出 256 個最相關詞彙，再切訓練與測試資料  
C. 在訓練資料上以支援 sparse input 的 randomized `TruncatedSVD` 擬合 256 個成分，再以同一轉換處理驗證與測試資料  
D. 對全部資料執行 t-SNE 產生 256 維特徵，並假設之後的新文件可直接用相同座標映射

## L22302 常見的大數據分析方法

### 第 5 題［高難｜不平衡資料與評估指標］

同一個詐欺評分模型部署到兩個市場。若兩市場的 `P(score | fraud)` 與 `P(score | non-fraud)` 相同，但詐欺盛行率分別為 1% 與 0.1%，團隊希望先比較模型的排序鑑別力，再估算各市場實際告警的命中率。下列敘述何者最正確？

A. 只要 accuracy 很高，就能同時代表排序能力與告警命中率  
B. PR-AUC 與任一固定門檻下的 precision 都不受盛行率影響  
C. 在條件分佈不變的假設下，ROC-AUC 可用來比較排序鑑別力；但 precision、PR 曲線及營運門檻仍應依各市場盛行率與成本重新估計  
D. 兩市場皆固定使用 0.5 門檻，即可保證相同 precision 與 recall

### 第 6 題［高難｜Average Precision 計算］

某二元分類器依分數由高到低排序後，完整的 8 筆測試資料真實標籤為：

`[1, 0, 1, 0, 1, 0, 0, 1]`

若 Average Precision 定義為「每遇到一筆正例時的 precision 之平均」，且不做插值，AP 約為何？

A. 0.692  
B. 0.750  
C. 0.500  
D. 0.875

### 第 7 題［中偏難｜大規模近似相似搜尋］

平台要從 3 億筆集合型商品瀏覽紀錄中找出 Jaccard similarity 很高的近重複紀錄。完整 all-pairs 比較不可行，但候選產生後可以再做精確 Jaccard 驗證。哪種設計最符合需求？

A. 對所有紀錄建立完整 `3億 × 3億` 距離矩陣，再做階層式分群  
B. 只比較每筆紀錄的總商品數；數量相同就視為近重複  
C. 將每筆集合先轉成一個平均商品編號，再以一維距離判斷 Jaccard similarity  
D. 使用 MinHash 近似 Jaccard similarity，透過 LSH 產生候選配對，再對候選執行精確驗證

### 第 8 題［高難｜不平衡取樣與交叉驗證］

某疾病分類資料正例僅占 0.5%。團隊要比較多組超參數，計畫使用 SMOTE 與 5-fold cross-validation，最後還有一份完全未使用的測試集。哪個評估流程最可靠？

A. 先對完整資料做 SMOTE，再切出測試集與 5 個 folds  
B. 先保留原始分布的測試集；每一 fold 僅在該 fold 的訓練部分擬合前處理並做 SMOTE，驗證部分維持原始分布；選定設定後才以訓練資料重建模型並評估一次測試集  
C. 對每個驗證 fold 也做 SMOTE 至 50:50，因為如此得到的 precision 最接近真實部署  
D. 每試一組超參數就查看測試集結果，最後挑測試分數最高者

## L22303 數據可視化工具

### 第 9 題［中偏難｜視覺編碼與共同基線］

分析師要比較 30 個地區的「實際值減目標值」，數值有正有負，且每個估計值都有 95% 信賴區間。讀者最關心偏離方向、幅度及是否跨過 0。哪種設計最佳？

A. 使用依估計值排序的水平點區間圖（forest plot），所有點共享以 0 為中心的同一數值軸，並以線段呈現信賴區間  
B. 使用 30 個大小不一的圓餅圖，扇形角度代表正負偏差  
C. 將每個地區各畫一條自動縮放的 y 軸，使地區內變化看起來更明顯  
D. 用 3D 氣泡的體積表示偏差，深度位置表示信賴區間

### 第 10 題［高難｜地圖聚合與分母］

各行政區人口相差超過 100 倍。團隊要用地圖比較罕見事件的風險；部分小行政區只有數十名居民，原始事件數也很少。哪種呈現最不容易誤導？

A. 直接以原始事件數做 choropleth，因為次數不需要分母  
B. 每個行政區只要出現 1 件就塗成同樣最深色，避免透露樣本數  
C. 呈現每十萬人口發生率，同時揭露事件數與人口分母，並用信賴區間或清楚標示的經驗貝氏平滑反映小樣本不確定性  
D. 將行政區面積當作人口分母，因為地圖已經呈現面積

### 第 11 題［高難｜預測不確定性］

需求預測模型要顯示未來 30 天的單日需求。使用者需要知道「未來實際觀測值」可能落在哪裡，而不只是平均需求估計的不確定性。哪個做法最佳？

A. 只畫一條點預測線；樣本量大時不確定性可以忽略  
B. 畫中位數預測與例如 50%、95% prediction intervals 的巢狀帶狀圖，並在時間外推的回測區間檢查實際涵蓋率  
C. 畫平均數的 confidence interval，並宣稱它必然包含 95% 的未來單筆需求  
D. 將訓練損失的標準差畫成固定寬度帶狀區，且不檢查殘差或回測涵蓋率

### 第 12 題［高難｜多解析度視覺化效能］

時間序列資料一天有 8,640 萬點，前端圖寬只有 1,200 像素；罕見但尖銳的瞬時峰值不可被平均掉，使用者還需要縮放後查看局部原始資料。哪個方案最合理？

A. 將全部 8,640 萬點各自畫成 SVG circle，再靠瀏覽器隱藏重疊點  
B. 每天只傳一個平均值；不論縮放層級都使用相同資料  
C. 在全資料中均勻隨機抽 1,200 點後連線，因為每個峰值都必然會被抽中  
D. 依目前 viewport 與像素寬度查詢相符時間桶，回傳每桶 min/max 等保峰摘要形成 envelope；縮放時提高解析度，必要時才讀取局部原始點
